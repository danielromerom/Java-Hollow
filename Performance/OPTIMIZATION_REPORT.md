# Java Hollow performance pass

Participant scene: `Assets/Terrain_Demo_For_Show.unity` (confirmed by the owner and the only enabled build scene). Branch: `codex/framerate-revision`. Unity 6000.2.9f1, URP 17.2.0, OpenXR 1.15.1, XRI 3.2.1. Target: Windows PC driving Quest 2; local hardware query identified i7-10750H / NVIDIA RTX 2060, plus Intel UHD and Meta Virtual Monitor adapters. Actual runtime, Link/Air Link settings, eye resolution and headset refresh rate still need recording.

**Status:** source/configuration audit and focused optimizations completed; target-HMD performance acceptance remains open. No measured 60+ FPS claim. No 30 FPS experimental condition was introduced. No objects, effects, audio, interactions, lights or vegetation were removed. Shader quality, MSAA, resolution scale, light intensities/ranges, LOD thresholds and experiment timing were preserved.

**Other audited areas**

- XR: Standalone OpenXR already requests Single Pass Instanced (enum value 1 verified in the installed package). One enabled stereo camera, both eyes, no render texture or camera stack, near/far 0.01/1000, occlusion enabled. No duplicate scene cameras found. Verify actual runtime mode and stereo shader correctness in-headset.
- URP: SRP Batcher on, standalone static batching on, dynamic batching off, terrain Draw Instanced on; render scale 1, MSAA 4, HDR on, optional global opaque/depth textures off, Forward renderer with no renderer features. Do not claim that enabling material instancing alone would replace SRP Batcher draws.
- Shadows / lighting / reflections: URP main shadow atlas 4096, distance 10, one cascade; additional-light shadows off. The legacy quality panel's 150 shadow distance is not the active URP shadow distance. No scene ReflectionProbe or LightProbeGroup components. LightingSettings enables baking but the resolved scene lights are all Realtime; this is not evidence that they are baked. Scene has a lighting-data reference. Baked occlusion data is absent, despite camera occlusion being enabled.
- Vegetation / meshes / LOD: 41 scene LODGroups, plus terrain tree prototype LODGroups. Mesh inventory ranks instance-weighted vertices; 2 macaron-tower instances have 12,528 vertices each, 7 bookshelves have 3,296 each; no arbitrary decimation performed. Some mesh assets retain CPU-readable copies. Do not remove Read/Write globally: mesh colliders and runtime consumers need checking per asset.
- Particles: billboard fireflies (world space, max 100, 20/sec, lifetime 5), local candle embers, smoke trails and campfire effects preserved. The reduced smoke system has no distance emission, bursts, subemitters or ring buffer. Bounds reported as zero in the headless, nonplaying inventory are NOT evidence of broken runtime bounds. Do not hard-code bounds from that snapshot. Billboard systems do not become GPU-instanced mesh particles by checking a flag.
- Materials / shaders: repeated shared materials already exist (e.g. coffee `basic`, lantern `lustre`, chair/table trims). Custom UberFX has URP, instancing and stereo macros. A legacy GrabPass glass shader occurs in the text dependency graph, but is not among the resolved renderer materials: do not mistake an imported dependency for active rendering cost. Some terrain prototypes come from Standard/HDRP asset folders; folder names alone do not establish active shader compatibility. Check foliage/glass in both eyes and inspect actual draws.
- Post-processing: participant camera post-processing off, no scene Volume component; imported post-process assets in other scenes are not current bottlenecks. No reason to strip atmospheric effects elsewhere.
- UI / animation: 12 canvases, 16 ContentSizeFitters, 24 animators, controller callouts and 23 camera-facing flame scripts. UI rebuilds and flame animation need profiling; no blanket disabling or tracking-frequency changes. `DisplayFPS` is not attached in the participant inventory. No `TreeFXController` attachment found there.
- Audio / timers / research: 6 AudioSources, 4 active; bird snippets use variable-delay coroutines, footsteps preserve existing movement thresholds, seating preserves its 0.2-second delay. One PlayableDirector remains unchanged. No research-specific timing/instrumentation was edited. Liquid Debug.Log is a developer diagnostic; define `JAVA_HOLLOW_VERBOSE_LIQUID_LOGS` to explicitly restore it if any external process was consuming that text.
- Runtime scripts: searched project C# for Update/FixedUpdate/LateUpdate, repeated lookup/material access, instantiation, collections, logging, physics queries, CPU texture reads and timing changes; followed participant prefab references. Vendor screenshot/order-generation utilities are not participant hot paths. DayAndNight's per-frame `DynamicGI.UpdateEnvironment` is inefficient if enabled but its component is disabled in this scene, so it was deliberately not modified or credited as a current improvement.
- Texture / memory: dependency inventory lists 66 textures at least 2048 pixels (or CPU-readable); all 66 are non-readable and compressed, streaming off. 59 have mipmaps; six menu images and one TMP icon atlas do not. UI mipmaps need a readability/shimmer comparison before changing. This is not a complete resident-VRAM measurement. No global compression or mip limit reduction. Incremental GC is already on. No existing runtime profiler/benchmark capture found outside generated caches/logs.

**Verification evidence**

- Unity headless audit completed successfully; 1,565 resolved GameObjects / 1,361 active, zero missing scripts in the Editor scene. See `scene-inventory.txt` (recorded before the smoke cap reduction; capacity there intentionally remains 100000).
- `liquid-validation.txt`: finite mixture, conservation, blend, sipping, emptying, full transfer, capacity clamp and infinite-source checks pass. 1,000 warmed transfer/removal cycles allocate 0 managed bytes on the calling thread with `liquidVisual=null`. This does not measure particle/renderer/native allocations or the complete frame.
- `particle-validation.txt`: 1,800 simulation steps at 1/60 second for each of three seeds; original 100000 versus 128 capacity. Counts, seeds, positions, remaining lifetime and start colors match; maximum 61 particles. Not a rendered-pixel or trail-image comparison.
- Windows x64 IL2CPP non-development build **succeeded with 0 build errors**, reported size 1,826,580,981 bytes. Executable: `Builds/PerformanceValidation/JavaHollow.exe` (keep its accompanying data/DLLs). Scene and prefab comparisons verify only the two intended serialized values changed; `git diff --check` passes. See `build-validation.txt`; local detailed log: `Logs/PerformanceBuild.log`. Interactive player/HMD acceptance has not been run.

**Rendering changes deliberately deferred**

No automatic Forward+ switch: with 191 lights it may improve light handling, but it can also expose lights excluded by Forward's per-object cap, changing appearance. No global static-flag sweep or mesh combining: moving interactables, animated flame billboards, wind shaders, culling granularity and duplicated vertex memory require object-level review. No global instancing toggle or SRP Batcher disable.

No light removal, baking conversion, intensity/range reduction, shadow/MSAA/render-scale reduction, foveation, LOD/density reduction, camera-distance reduction or replacement shader. No AlwaysSimulate-to-Pause conversion: offscreen particles can still matter through lighting/trails, and PauseAndCatchup can move work into a visible-frame spike. No tighter bounds without observed runtime extents. No physics-timestep/AutoSyncTransforms change, audio pruning, or experimental cadence cap.

Recommended next, after a CPU/GPU capture: A/B test Forward+ and selectively baked/mixed static mushroom/lantern lighting with approval for any visible differences; evaluate static batching of verified immobile opaque decorations; bake occlusion around genuinely opaque café geometry and verify every participant route; test offscreen simulation policy on isolated noninteractive effects; inspect terrain foliage overdraw/LOD and memory residency. Keep original variants for visual comparison. These are recommendations, not implemented/proven gains.

**Editor checks**

2. Inspect the XR camera's FPSCap (-1), candle smoke (128), and unchanged emission/lifetime/trails. Compare flames/smoke/fireflies while standing close, looking away, returning and teleporting.

**Standalone checks**

1. Run the full-quality Windows build on AC power using the RTX 2060. Confirm actual adapter, resolution, quality level, pipeline and scene in the player/profiler. Compare using the same quality level; Editor VR and standalone Medium differ.
2. Repeat all interactions and the participant route, including looking through the densest foliage and toward the mushroom/lantern cluster and fire. Compare appearance with baseline screenshots at matching poses; particle randomness is expected.
3. Warm up 60 seconds, then capture at least 60–120 seconds plus a 10-minute soak for GC, memory growth, shader warmup and laptop thermal throttling. Check player errors and missing materials. Uncapping alone does not prove optimization or smooth pacing.
